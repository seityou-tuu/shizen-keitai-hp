# MacBookで使うHP運用マニュアル

対象リポジトリ：`seityou-tuu/shizen-keitai-hp`  
正式URL：https://shizen-keitai-hp.vercel.app/  
今回の作業：PR #6 / `feat/program-site-renewal`

## 1. 最初に知っておくこと

GitHubは原稿や写真を置く場所です。Vercelは、その原稿からホームページを作って表示するサービスです。「ブランチ」は作業用のコピー、「Pull Request（PR）」は変更を見比べる確認画面、「マージ」は承認した変更を本体へ取り込む操作です。

**mainは現在の公開サイトにつながっています。** 編集は作業ブランチで行い、Vercelのプレビューで確認してから管理者が公開を判断します。今回はmainをマージ・公開していません。

## 2. GitHubで更新する流れ

1. MacBookのSafariやChromeでGitHubにログインし、対象リポジトリを開きます。
2. **Pull requests → #6** を開きます。作業ブランチ名が`feat/program-site-renewal`であることを確認します。
3. 原稿を自分で編集する場合は、Code画面のブランチ選択で作業ブランチに切り替えます。mainを直接編集しないでください。
4. 対象ファイルの鉛筆アイコンで編集します。保存時は変更内容を短く説明します（例：「講師プロフィールの確認済み情報を追加」）。
5. PR #6に変更が追加されたことを確認します。新しい作業をPR #6のマージ後に始める場合は、最新mainから別の作業ブランチとPRを作ります。

分からない場合は、自分でコードを直す代わりにCodexへ依頼できます。

## 3. Codexへの依頼例

> seityou-tuu/shizen-keitai-hpのPR #6の変更を維持し、同じブランチへ追加してください。変更したい箇所は○○です。確認済みの新しい文章は「○○」です。料金・会社情報・規約は変更せず、mainへのマージや本番反映はしないでください。ビルド・型チェック・テストを行い、Vercelプレビューの確認方法と未確認事項を報告してください。

住所・電話・資格・認定条件・支払い・返金等を変える場合は、「主催者確認済み」の文章と対象箇所を明記してください。未確認の内容を補完するよう依頼しないでください。

## 4. PRを確認する

1. PR #6の **Files changed** で、緑が追加・赤が削除された箇所を確認します。
2. タイトルと説明を読み、「どの情報が変わり、何が未確認か」を確認します。
3. PR下部のチェック欄でVercelが成功しているかを確認します。成功はビルド完了を示しますが、内容の正しさやメール到着まで保証するものではありません。
4. 見た目は次のプレビューで確認します。修正が必要なら、対象箇所と望む状態をCodexへ伝えます。

## 5. Vercelプレビューで確認する

1. PR #6のVercelチェックの **Details**、またはVercelのプロジェクト → **Deployments** を開きます。
2. ブランチが`feat/program-site-renewal`で、最新コミットと一致するデプロイを選びます。古いデプロイやProductionを選ばないでください。
3. **Ready** になったら **Visit** から開きます。認証を求められた場合は、権限のあるVercelアカウントでログインします。
4. 最初はMacBookで確認します。幅を狭めても、文字・料金・写真が隠れないか確認します。
5. iPhoneのSafariでも同じプレビューURLを開き、縦向き・横向きで確認します。Macだけでは実機の確認の代わりになりません。

確認すること：

- トップの見出しが自然に改行される、写真の人物が切れたり伸びたりしない。
- 画面を左右にずらさなくても読める。料金が途中で切れない。
- メニュー各項目が正しい見出しへ移動し、固定ヘッダーに隠れない。
- 受講相談ボタンが問い合わせ欄へ移動する。
- 電話リンクをタップすると`0985-74-7643`の発信確認になる。確認のために実際に発信する必要はありません。
- 下部の固定案内が文章やフォームを隠さない。入力時のキーボード表示も確認する。
- FAQがタップで開閉する。MacではTabで移動しEnterまたはSpaceでも操作できる。
- メニューをEscapeで閉じられる。フォーム項目やリンクのフォーカス枠が見える。
- 各コース990,000円（税込）、3コース合計2,970,000円（税込）、期間・実技・理論の条件が正しい。
- 会社概要・特商法・受講規約・プライバシーポリシーのリンクが開く。

## 6. お問い合わせフォームを設定する

### 先に決めること

主催者が受信先メール、担当者、返信手順、保存期間・削除方法を決めます。Formspree利用に伴う個人情報の扱いと既存ポリシーの不整合は[確認リスト](payment-review-checklist.md)を参照してください。架空のアドレスを使わないでください。

### 接続

1. https://formspree.io/ に登録し、新しいフォームを作成します。
2. 本当に受信できるメールアドレスで受信先の確認手続きを済ませます。
3. 接続先URL末尾のフォームIDをコピーします。`https://formspree.io/f/`より後の英数字だけです。
4. Vercel → 対象プロジェクト → **Settings → Environment Variables** に進みます。
5. 名前：`FORMSPREE_FORM_ID`、値：実際のフォームID。まず **Preview** だけを選択して保存します。
6. **Deployments**で作業ブランチの最新デプロイを選び **Redeploy** します。すでに開いているプレビューも更新します。
7. 「フォーム送信は現在準備中です」が消え、入力できることを確認します。
8. テストと明記して1件送信し、Formspree管理画面と受信メールの両方で到着を確認します。テストにも病歴・カード番号等は入れないでください。
9. スパム対策、許可ドメイン、利用上限・課金条件をFormspreeで確認します。プラン・設定によりCAPTCHA等がAPI送信を拒否する場合は、機能を止めて設定を確認してください。
10. 本番利用の準備が整った後、Productionにも変数を設定します。本番反映は管理者がマージを判断した後です。

### 画面の確認

- 未設定：入力・送信が無効で電話案内が表示される。未設定のAPI呼び出しも成功しない。
- 設定済みで空欄：送信すると必須項目のエラーが出る。メール形式、同意、文字数も確認する。
- 送信中：ボタンを連打できない。自動再送はしない。
- 成功：Formspreeが受け付けた場合だけ表示する。「メールが必ず届いた」こととは区別し、受信箱も確認する。
- 失敗：成功と表示されない。入力内容は維持される。
- 通信結果が不明：受信済みの可能性もあるため、Formspreeの受信一覧を確認してから判断する。何度も再送しない。
- 未設定へ戻す：変数を削除/空欄にし、再デプロイする。受付済みの情報はFormspree・メール側で別途管理する。

実メールを使う接続確認は、アカウントと受信先を用意した管理者が行います。コードの自動テストでは外部送信を模擬しており、実際のメールを送りません。

## 7. mainへマージする方法（管理者が公開を決めたときだけ）

**この項目は操作説明です。今回の作業でマージは実行していません。**

1. 未確定の法定情報・運用条件を確認し、必要な修正が別途承認されていることを確認します。
2. 最新PRのVercelチェックと、プレビューのPC・iPhone Safari確認、フォームを有効にする場合は実送受信確認を済ませます。
3. PRの **Merge pull request → Confirm merge** で取り込みます。ボタンが無効の場合は保護ルール・失敗したチェックを確認し、強制的な回避はしないでください。
4. mainへの取り込みでVercelの本番ビルドが始まる構成です。Productionの環境変数も確認します。
5. **Ready** になった後、正式URLを開いて確認します。

## 8. 公開後の確認と検索設定

- 正式URL、電話、メニュー、FAQ、料金、フォーム、4つの情報ページを再確認します。
- canonicalとOGP画像のURLは正式URLへ統一しています。
- 既存の検索登録停止を初期値として維持しています。法定情報と公開準備が整い、主催者が検索登録を希望する場合は、Vercelの**Productionのみ**`SITE_INDEXING_ENABLED=true`にし、再デプロイしてください。
- Previewはこの値がtrueでもnoindexです。`robots.txt`では巡回を拒否し、sitemapは空になります。非公開・認証の代わりにはならないため、秘密の資料は載せないでください。
- Productionで検索登録を有効にすると、`/robots.txt`はAPI以外を許可し、`/sitemap.xml`は正式URLの5ページを出力します。設定後に実際の応答を確認してください。
- 検索順位・掲載時期は保証されません。構造化データは事業者名・サイト名・電話等の確認済み情報だけです。

## 9. 写真を追加・差し替える

写真は`public/images/`にあります。現在の8枚は1回ずつ使用しています。

| ファイル                  | 用途                                               |
| ------------------------- | -------------------------------------------------- |
| treatment-main.jpg        | トップの施術紹介                                   |
| treatment-detail.jpg      | 施術の補助紹介                                     |
| practical-hands-on.jpg    | 実技研修                                           |

| classroom-session.jpg     | 対面座学の参考写真（オンライン画面ではないと明示） |
| group-guidance.jpg        | 研修の雰囲気                                       |

同じファイル名で差し替える場合も、作業ブランチでアップロードしてPR・プレビュー確認を行います。縦横比や写真内の人物の許諾を確認してください。画像サイズを大きく変えた場合はスマートフォンでも確認します。新しいファイル名を使う場合は`components/program-photo.tsx`の対応と画像説明も更新する必要があるため、Codexへ依頼すると安全です。

通常の施術写真を公開施術の実績として使わないでください。掲載許諾がない写真や未確認の症例説明は追加しないでください。

## 10. 文章を変更する

主な原稿・FAQ・コース紹介は`app/page.tsx`、画像の説明は`components/program-photo.tsx`と各呼び出し箇所、問い合わせ入力は`components/contact-form.tsx`、表示調整は`app/renewal.css`と`app/contact.css`です。

会社・法定情報は`lib/site-information.ts`と`app/(information)/`にあります。確認済みの正式な文章がある場合だけ、主催者の承認範囲で更新してください。電話相談の番号は`lib/contact-validation.ts`です。現在、法定情報の電話欄は未確認のままなので、相談番号を変えたら法定情報も自動で変更される構成ではありません。

正式な契約・返金・認定条件、受付時間、プロフィール、動画期限、回答時間などは推測で埋めないでください。

## 11. エラー時の対処

| 症状                     | 対応                                                                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Vercelが失敗（Error）    | 対象デプロイのBuild Logsを確認。エラー文・ブランチ・コミットをCodexへ伝える。秘密情報や個人情報は貼らない。                                |
| 写真が出ない             | ファイル名と大文字小文字、拡張子、GitHubへのアップロード、対象ブランチを確認。                                                             |
| フォームが準備中         | 正しいPreview/Productionに`FORMSPREE_FORM_ID`が設定済みか、IDだけか、再デプロイしたかを確認。                                              |
| 受付完了だがメールがない | Formspreeの受信一覧、受信先認証、迷惑メール、通知設定、利用上限を確認。成功表示はFormspreeの受付確認であり、配送保証ではない。             |
| 送信失敗・混雑           | 電話案内を利用。Formspreeの利用上限・スパム設定・ドメイン許可・サービス状態を確認。入力本文をログへ追加しない。                            |
| レイアウトが変           | Safariを再読み込みし、最新プレビューで確認。画面幅・端末・該当箇所をCodexへ伝える。                                                        |
| 公開後に大きな問題       | まずVercelとGitHubの最新変更を確認。必要なら管理者が前の正常なデプロイへ戻す。データの削除や強制pushをしない。元のフォーム設定も確認する。 |

## 12. 技術担当者の確認コマンド

Node.js 24.xを推奨します。

```sh
npm ci
npm test
npm run build
npm run typecheck
git diff --check
```

Lintの設定はありません。自動テストは外部送信を模擬し、入力検証・送信失敗・未設定・同一送信元・サイズ上限・プレビューの検索除外を検査します。ブラウザ、実配送、iPhone Safari、実測性能は別途確認が必要です。

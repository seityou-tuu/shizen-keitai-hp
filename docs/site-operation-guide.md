# MacBook・Chromeで使うHP運用マニュアル

対象：`seityou-tuu/shizen-keitai-hp`
作業中：PR #6 / `feat/program-site-renewal`
正式URL：https://shizen-keitai-hp.vercel.app/

## 1. 更新の基本

GitHubは文章・写真・設定を置く場所、VercelはそこからHPを表示するサービスです。「ブランチ」は作業用コピー、「Pull Request（PR）」は変更を見比べる確認画面、「マージ」は承認した変更を本体へ取り込む操作です。

**mainは現在の公開サイトにつながっています。** 文章・写真・電話・LINEの変更も作業ブランチで行い、プレビューを確認してから管理者が公開を判断します。今回の作業ではmainへのマージ・本番反映は行っていません。

## 2. HPの文章を変える

1. MacBookのChromeでGitHubにログインし、対象リポジトリを開きます。
2. Code画面のブランチ選択で`feat/program-site-renewal`を選びます。mainを直接編集しないでください。
3. 主な文章・FAQ・コース説明は`app/page.tsx`です。対象ファイルを開き、鉛筆アイコンで編集します。
4. タグや記号を壊さないよう文章部分だけ変更します。難しい場合はCodexへ依頼してください。
5. 保存時は変更内容を短く説明します。PR #6へ変更が追加されたことを確認します。
6. Vercelの最新プレビューで、文章の改行・料金・リンクを確認します。

料金・認定条件・支払い・解約・返金・会社情報は、主催者が確認した正式文面だけを反映します。未確認情報を見た目の完成のために補完しないでください。

## 3. 写真を変える

現在の8枚は`public/images/`にあり、各1回ずつ使っています。

| 写真                      | 用途                                                   |
| ------------------------- | ------------------------------------------------------ |
| treatment-main.jpg        | トップの施術紹介                                       |
| treatment-detail.jpg      | 施術の補助紹介                                         |
| practical-hands-on.jpg    | 実技研修                                               |
| practical-observation.jpg | 実技の観察                                             |
| classroom-session.jpg     | 対面座学の参考写真。オンライン研修の画面ではないと説明 |
| group-guidance.jpg        | 研修の雰囲気                                           |

同じ名前で差し替える場合も、作業ブランチでアップロードしてPR・プレビュー確認を行います。人物の許諾・写真の向き・縦横比を確認してください。ファイル名を変える場合は`components/program-photo.tsx`と呼び出し箇所の変更も必要です。Codexへ依頼すると安全です。

通常の施術写真を公開施術の実績写真として使用しないでください。未確認の症例や成果の説明を追加しないでください。

## 4. Codexへの修正依頼

次のように、対象・確認済み文章・変更しない範囲を伝えます。

> seityou-tuu/shizen-keitai-hpのPR #6を引き継ぎ、同じ作業ブランチへ追加してください。修正箇所は○○です。主催者確認済みの文章は「○○」です。その他の会社情報・料金・規約は変更せず、mainへのマージや本番反映はしないでください。ビルド・型チェック・テストと、Vercelプレビューの確認結果・未確認事項を報告してください。

PR #6の公開後に新しい作業を始める場合は、最新mainから新しい作業ブランチとPRを作ります。

## 5. GitHubのPRを確認する

1. **Pull requests → #6** を開きます。
2. 説明を読み、変更点と未確認事項を確認します。
3. **Files changed**で、緑の追加・赤の削除を見比べます。
4. PRのチェック欄で、最新コミットのVercelが成功しているか確認します。
5. ビルド成功だけでは、料金・法定情報の正しさや実画面の操作まで確認済みとは限りません。次の手順も行います。

## 6. Vercelプレビューを開く

1. PR #6のVercelチェックの **Details** をクリックします。またはVercelの対象プロジェクト → **Deployments**を開きます。
2. ブランチが`feat/program-site-renewal`で、最新コミットと一致するデプロイを選びます。古いデプロイやProductionは選ばないでください。
3. **Ready**になったら **Visit** で開きます。ログインを求められたら、権限のあるVercelアカウントでログインします。
4. MacBookのChromeで全体を確認し、ウィンドウ幅を狭めても文章やボタンが切れないか見ます。
5. 同じURLをiPhone Safariでも開き、縦向き・横向きで確認します。Chromeの画面幅変更だけでは実機確認の代わりにはなりません。

[公開前チェックリスト](pre-launch-checklist.md)を使い、見出し・写真・ナビゲーション・電話・FAQ・料金・フッター・法定ページを確認してください。未確認項目のチェックを先に入れないでください。

## 7. 公式LINEのURLを設定する

**現在、公式LINEは未開設です。空欄のままで電話を正式窓口として利用できます。**

1. 主催者が公式LINEを開設し、正式なアカウント名・管理者・対応担当を決めます。
2. LINEの管理画面から、公開用の「友だち追加URL」を取得します。管理画面のURL・ログイン情報・アクセストークンではありません。
3. URLを自分の端末で開き、実在する正しい公式アカウントであることを確認します。
4. GitHubで**作業ブランチ**を選び、`lib/contact.ts`を開きます。
5. 次の設定の引用符の間に、確認済みの友だち追加URLを入れます。

```ts
export const OFFICIAL_LINE_URL: string = "";
```

6. 変更を保存し、PRのチェックとVercelプレビューを確認します。**この1か所で、トップ・研修後・料金後・問い合わせ欄・スマホ下部など、HP内のすべてのLINE相談ボタンへ反映されます。**
7. 各ボタンをクリックし、正しいアカウントへ移動することを確認します。PCとスマートフォンの両方で確認してください。
8. LINE対応が実際に開始できる状態か確認し、管理者が公開を判断します。

URLが空欄または不正ならLINEボタンは非表示です。HTTPSの`lin.ee`短縮URLか`line.me`の友だち追加URLに対応しています。別ドメイン・認証情報付きURL・管理画面のURLなどは表示しません。形式の確認だけではアカウントの実在や所有者は確認できないため、必ず手順3と7を行います。

停止する場合は同じ設定を空欄に戻してPR・プレビューで確認します。環境変数へのLINE URLの重複登録や、ボタンごとのURL編集は不要です。QRコードはこのHPには設置していません。

LINEの受付時間・返信時間・個人情報の扱い・対応範囲は、運営で決まった内容だけを案内します。管理用認証情報をGitHubやHPへ貼り付けないでください。

## 8. 電話番号を変更する

1. 主催者に新しい正式相談番号と、掲載してよい範囲を確認します。
2. 作業ブランチの`lib/contact.ts`で`CONTACT_PHONE`を変更します。
3. 発信リンクはその番号から自動で作られ、トップ・相談ボタン・最下部・フッター・構造化データに反映されます。
4. 電話番号を確認する自動テストの期待値も、確認済みの新番号に合わせてCodexへ更新を依頼します。
5. プレビュー上で表示番号と発信先を確認します。確認のために実際の通話は不要です。

会社概要・特商法の電話欄も同じ共通設定を参照します。電話を変更する際は、事業者の確認済み番号だけを使い、全ページの表示と発信先を確認してください。住所・受付時間・契約条件を推測で追加しないでください。

## 9. mainへマージする（管理者が公開を決めたときだけ）

**以下は操作説明です。今回の作業でマージは実行していません。**

1. [決済審査リスト](payment-review-checklist.md)と[永友先生への確認事項](nagatomo-confirmation-list.md)を確認します。
2. 未確定の法定情報・契約条件・公開範囲について主催者の判断を得ます。
3. 最新PRのチェック・Vercel Ready・PC/iPhoneの実画面確認を済ませます。
4. PRで **Merge pull request → Confirm merge** を選びます。ボタンが無効の場合は、失敗したチェックや保護ルールを確認し、強制的な回避をしないでください。
5. mainへの取り込みでVercelの本番ビルドが始まる構成です。ProductionがReadyになった後、正式URLを開きます。

## 10. 本番HPの更新を確認する

- 正式URLで、写真8枚・電話・FAQ10項目・料金・ナビゲーション・4つの情報ページを再確認します。
- LINEを接続した場合は、本番でも正しい公式アカウントが開くことを確認します。
- 本番の公開確認とプレビュー確認は別です。今回の作業では本番へ直接変更していません。
- canonicalとOGPは正式URLへ統一しています。プレビューは常にnoindexです。
- 既存の検索登録停止を初期値として維持しています。公開準備後に検索登録を希望する場合は、Vercelの**Productionのみ**`SITE_INDEXING_ENABLED=true`にして再デプロイします。Previewはtrueでも検索登録を許可しません。
- 検索登録が有効な本番では`/robots.txt`と`/sitemap.xml`が正式URLを案内します。無効時は巡回拒否・空のsitemapです。設定後は実際の応答を確認してください。
- 検索除外はアクセス制限ではありません。機密資料や相談者の個人情報はHPや公開GitHubへ置かないでください。

## 11. エラーが起きたら

| 症状                     | 確認すること                                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| VercelがError            | 対象ブランチ・コミット・Build Logsを確認し、エラー文をCodexへ伝える。個人情報や秘密情報は貼らない。                |
| 古い表示のまま           | 最新デプロイがReadyか確認し、Chromeで再読み込みする。古いプレビューURLや別ブランチを見ていないか確認する。         |
| 写真が出ない             | ファイル名・大文字小文字・拡張子・アップロード先・対象ブランチを確認。                                             |
| LINEボタンが出ない       | `OFFICIAL_LINE_URL`が空欄ではないか、友だち追加URLの形式か、作業ブランチへ保存し最新デプロイを開いているかを確認。 |
| 違うLINEアカウントが開く | 公開しない。主催者へ正しいURLを確認し、必要なら空欄へ戻して非表示にする。                                          |
| 電話番号が違う           | `CONTACT_PHONE`と表示・発信リンクの一致を確認し、主催者承認の番号へ修正する。                                      |
| スマホで読みにくい       | 端末・画面幅・該当箇所をCodexへ伝える。実画面で確認するまで修正完了とは扱わない。                                  |
| 公開後に重大な問題       | 最新変更を確認し、必要なら管理者が前の正常なデプロイへ戻す。データ削除や強制pushは行わない。                       |


## 13. ローカルのブラウザ確認（技術担当者向け）

既存のPlaywrightとChromiumがある環境では、ビルド後にローカルサーバーを起動し、`npm run test:browser`で確認できます。標準の`npm test`とは別の任意チェックで、製品の依存ライブラリにはPlaywrightを追加していません。

- `QA_BASE_URL`：ローカルURL。省略時は`http://127.0.0.1:3100`。
- `PLAYWRIGHT_MODULE_PATH`：既存Playwrightを通常の場所から読み込めない場合のモジュールパス。
- `CHROMIUM_EXECUTABLE_PATH`：既存Chromiumの実行ファイルを指定する場合。
- `QA_OUTPUT_DIR`：結果JSON・確認画像を一時保存する場合の作業ディレクトリ。公開用の`public/`は指定しないでください。

320/360/375/390/414/430/768/1024/1440px、FAQ10件の開閉と番号、メニュー、電話/窓口案内、固定CTAとフッター、画像比率、料金、情報ページを検証します。LCP・CLSはローカルの非スロットル環境の参考値で、iPhone実機やVercelの実測・一般利用者の指標とは別です。

## 14. 計測とVercel Toolbar

[アクセス解析の導入設計](analytics-measurement-plan.md)は資料のみです。計測SDK・タグ・Cookie・外部送信を追加していません。将来接続する場合も、電話/LINEのクリックを相談成立や申込みとみなさず、個人情報を送信しない設計を主催者と確認します。

Vercel Toolbarはプレビュー確認用です。管理画面の設定と、本番URLをChromeのシークレットウィンドウ（Vercelからログアウトした一般閲覧者）で開いた表示を、管理者が確認してください。リポジトリにToolbarを追加するコードはありませんが、Vercel側の注入設定はコードからは判断できません。今回Production設定は変更していません。

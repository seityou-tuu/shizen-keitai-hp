# GA4・Search Consoleの準備と有効化条件

2026年11月6日（日本時間）。PR #13反映後の改善ブランチで用意した手順です。現在は正式ID・確認コード未設定、GA4は無効です。GoogleやVercelの管理画面は変更していません。

## GA4：有効化前に運営者が確認すること

1. 管理対象のGA4プロパティ・Webストリームを確定し、そのストリームの正式な測定IDを取得します。書式の検証だけでは所有者や接続先の正しさは保証できません。
2. プライバシーポリシーの準備ページを正式な方針に更新します。Googleへの送信、Cookie、IP・端末情報、委託・国外での取扱い、保管期間、閲覧担当、削除・問い合わせ方法、同意と停止方法を、実運用・契約に沿って責任者が確認してください。今回、未確定の法的文面は補っていません。
3. GA4管理画面で**拡張計測機能をすべてOFF**にします。履歴変更のページビュー、スクロール、離脱クリック、サイト内検索、フォーム、動画、ダウンロード等の自動計測を追加しないでください。別のGTMタグ、Vercel注入タグ、GA設定との重複も確認します。コードの`send_page_view: false`だけで管理画面の全自動計測を無効にしたとは扱いません。
4. Google Signals、広告向け利用、ユーザーID連携を有効にしない構成です。保持期間やデータ共有等の管理画面設定も運営者が決定・確認してください。GAの通常の識別子・Cookie・端末情報等まで扱わない構成とは断言できません。
5. 上記の確認後、Vercelの**Productionのみ**に`GA4_MEASUREMENT_ID`を正式IDで設定し、`GA4_ENABLED=true`にして再ビルド・再デプロイします。現状の`.env.example`はID空欄・有効化falseです。Preview/Developmentには設定しません。今回の作業では設定・公開していません。
6. 正式環境で同意前にGoogleへの解析通信がないこと、許可・停止・ページ離脱、DebugView/Realtimeの受信、拡張計測OFF、Cookieの扱いを確認します。ローカルの置換テストはGoogleへの実配送を検証していません。

Production判定・有効化フラグ・有効な書式のIDが揃ったときだけ、トップページ末尾に解析の選択欄が表示されます。訪問者が「許可する」を選ぶまでGoogleのスクリプトは読み込みません。「許可しない」は無通信のまま、「停止する」は以後の電話クリック送信を止め、Googleの無効化フラグとanalytics_storage拒否を設定します。過去に送信済みのデータを削除する操作ではありません。GoogleのCookieがすでにある場合、その削除はブラウザー設定等で別途行う必要があります。

選択はページ内のメモリーだけで保持し、同意の保存用Cookie/localStorageは作成しません。再読込やトップページから離れて戻った場合は再度許可が必要です。情報ページへの移動時は処理を停止します。CMPとの統合や同意の永続保存は未実装です。正式運用に適した同意の方法・文面は責任者が確認してください。

## 実装した計測の範囲

| イベント | 発生条件 | 自前コードから渡す値 |
| --- | --- | --- |
| `page_view` | トップページで許可した後、同じdocument内で1回 | 正式トップURL、固定のサイト名、空の参照元 |
| `phone_click` | 許可後、正式電話リンクを操作したとき | 固定の設置場所（hero / roadmap / courses / contact / footer / sticky / other）、正式トップURL、空の参照元 |

電話番号・問い合わせ本文・任意テキスト・実際のクエリ/ハッシュ/参照元URLはイベント値に渡しません。電話クリックは、実際の発信・応対・問い合わせ成立・申込み・売上を示しません。LINEは未開設のため計測もリンクも追加していません。コース閲覧や動画視聴イベント、全ページのSPA閲覧計測は追加していません。

スクリプトの読込みと自動ページビューを重複させず、再許可でもページビューは同じdocumentにつき1回です。イベントリスナーは再初期化時に置き換え、停止・ページ離脱時に解除します。許可後のGoogle通信障害でも電話リンクの既定動作を妨げません。

## Search Console

1. 対象プロパティと所有者を確認します。ドメインプロパティならDNS TXTによる確認が必要で、HTMLタグの実装だけでは確認できません。DNS設定はこの作業では変更していません。
2. URLプレフィックスプロパティでHTMLタグ方式を使う場合、Search Consoleが発行したタグの`content`値だけを`GOOGLE_SITE_VERIFICATION`に設定します。正式値が未設定ならmetaタグは出ません。Productionのみ出力します。仮コードやタグ全体は設定しません。
3. 反映には再ビルド・管理者による公開が必要です。公開HTMLで正しいタグが1件出ることを確認し、所有者がSearch Consoleの確認操作を行います。所有権確認の完了は未検証です。
4. 現在の検索登録停止は維持しています。所有権確認と、検索公開を許可する判断は別です。法定情報等の確認が完了し責任者が検索公開を承認するまで、`SITE_INDEXING_ENABLED`を変更しません。
5. 承認後にProductionのみ検索登録を有効化し、robots.txt / sitemap.xml / URL検査を確認してからサイトマップを登録します。停止中のsitemapは空です。公開パスはトップ・会社概要・特商法・プライバシー・規約の5つに限定し、未マージのPR #9の募集ページは追加していません。

## 検証と制限

単体テストはProduction/Preview・フラグ・ID/確認コードの有効/無効、イベント値の制限、リスナーの重複防止、停止を検証します。`scripts/analytics-browser-check.cjs`は隔離したReact StrictMode画面で拒否・許可・停止・再許可・離脱を確認します。テスト用IDはテスト内の合成データのみで、環境設定・アプリルート・公開ビルドには設定しません。外部通信はすべてテスト側で置き換え、Googleには送信しません。

本番ドメインへの読み取りとGitHub APIが環境の接続制限で403になっているため、実際の本番タグ・プラットフォーム側のタグ注入・Google管理画面・データ到達は未確認です。

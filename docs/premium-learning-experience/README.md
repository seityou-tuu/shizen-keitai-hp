# プレミアム学習体験の改善

基準: `bbd5a663bc0637761f83acac62bb6caf6b728a7d`（PR #25・#27反映後のmain）。ブランチ: `feat/premium-learning-experience`。2026-11-18。

## 調査と変更範囲

通常HPは、ファーストビュー→療法の考え方→4つの視点→対象者→学習支援→実技/理論→3コース→講師/動画→Instagram→成長ストーリー→料金→FAQ→相談、という既存の流れを持っています。募集ページと会社・法定・プライバシー・規約ページも既存構成を確認し、今回の改修対象は通常HPの読み取りにくさが確認できた部分に限定しました。

新しいセクション・学習制度・資格条件・効果表現は追加していません。既存の5つの成長視点、3コース、動画リンク、相談窓口を使っています。

|対象|改善前に確認した弱点|改善後|
|---|---|---|
|成長ストーリー|スマホではアイコンが説明より上にあり、各段階が縦に長い。タブレットも5列で本文が細かく折り返す|スマホは番号・アイコンを左、説明を右に配置。701〜1100pxは幅のある行表示。1101px以上の上昇する図解は維持|
|3コース紹介|PCの3列は上下にずれていて、見出し・説明を横に比較しにくい|共通の細いゴールド軸にSTEPを並べ、見出しの高さを揃える。既存の順序・説明・各6ヶ月・料金へのリンクを維持|
|料金表|スマホではSTEPとコース名の間にも余白があり、同じ項目の比較に長いスクロールが必要|STEPと名称を同じ行へ。金額の大きさ、税込/税抜、期間、説明、総額、すべての注意書きを維持|
|講師紹介の動画2本|小さなサムネイルの横で再生数が大きく表示され、画像・外部操作・出典をまとまりとして読み取りにくい|同じ大きさの2列へ統一。サムネイル→YouTube操作→再生数/出典を同じ順序にする。画像全体をcontain表示し、表示幅に合わせてNext Imageのsizesだけ調整|
|相談への導線|中間の相談枠では補助リンクが縦に並ぶ。最後のLINE相談の近くには募集詳細リンクがない|スマホの補助リンクを2列に整理。最後のLINE欄を既存色の枠でまとめ、料金後半にあった募集詳細リンクを移動。リンク総数・接続先・文言は増減なし|

料金欄から移したリンクは `/recruitment/first#cohort-tuition` のままです。最後に詳細条件を確かめる経路として配置し、主ボタンは既存LINE相談を維持しました。相談だけでは正式申込み・契約・決済にならないという説明もそのままです。

## スマホとタブレットの違い

390pxの実測では、成長ストーリーは1811→1521px、料金セクションは4117→3772px。文言を削らず、配置・余白・既存リンクの移動で整理しました。

768pxの成長ストーリーは1267→1513pxです。タブレットでは短さよりも、5列の狭い本文を解消することを優先しています。全画面で一律にページを短くする変更ではありません。

## 維持した内容

- ファーストビュー、スプラッシュとロゴ、動的背景・ゴールド粒子・サイドナビの実装とCSSは差分なし。既存の深緑・白・ゴールドを使用。
- 講師写真・提供画像・動画ソース・Instagramの画像/URLは差し替えなし。動画2本のサイズ指定以外は既存素材の対応付けを維持。
- 4幅（390/768/1024/1440px）で本文を比較。移動した募集詳細リンクと表示上の空白を除いて全文一致。リンク先とラベルの一覧、画像ソースとaltの一覧も一致。
- 同じ4幅で、Canvasだけを比較撮影時に一時非表示にしたファーストビューの全画素が一致。背景の画素比較を主張するものではなく、通常の背景動作は別の検証で確認。
- 料金・日程・契約条件・募集状態・講師の実績・資格条件、LINE/電話接続先、SEO/noindex/robots/sitemap、Search Console、Vercelの環境設定は変更なし。
- 募集ページのコード・CSS、情報4ページは変更なし。Instagramは既存の構成と外部リンク方式で十分なため変更なし。
- 新規のアニメーション・クライアント処理・ライブラリは追加なし。既存のスクロール演出とreduced-motion対応を再利用。
- PR #28のブランチ・ファイル変更・PR操作は行っていません。本ブランチはmainから分岐しています。

## パフォーマンス

最初の前後各3回の測定はPerformance中央値85→91、LCP中央値2.211→2.633秒、TBT中央値402→189.5ms、CLSは双方0でした。LCPの増加があったため、基準コミットを別worktreeで起動し、同条件で前後を交互に3回ずつ追加測定しました。

Lighthouse 13.6.0、ローカルProduction Build、Chromium、既定のモバイル模擬スロットリング。各回新しいブラウザで、他のブラウザ検証と並列実行していません。以下は追加の交互測定の中央値です。

|項目|Before|After|
|---|---|---|
|Performance|90|88|
|LCP|2.654秒|2.633秒|
|TBT|241ms|310ms|
|CLS|0|0|

追加測定ではLCPはほぼ同程度でした。大幅なPerformanceスコア低下は見られませんが、TBT中央値は増加しています。小標本の模擬計測で変動もあるため、全面的な速度改善とは扱いません。初回と追加の全測定値をresults.jsonに残し、Preview・実機の速度確認は手動確認事項にしています。TBTを実ユーザーINPとして扱っていません。

今回の新規スタイルは約5.5KBのソースCSSです。動画は既存の外部リンク方式のままでiframe・外部プレーヤーの初期読み込みはありません。サムネイルが大きくなった分は表示幅に対応する画像を遅延読み込みします。実機の電力消費・実ユーザーINP・実回線の速度改善は未測定です。
